2026-06-30 — Fase 0: Mobile parity

Problema: las fichas de scripts.qmd y recursos.qmd se veían distintas a las de lecturas.qmd en móvil (≤600px). La causa: lecturas usa .book-img (portrait 104×150px) mientras que scripts y recursos usan badges cuadrados (.script-ext, .resource-badge, 92×92px). Al colapsar a columna vertical, los badges quedaban descentrados y sin estilos de compensación, generando una composición visual inconsistente.

Solución aplicada en theme.scss (sección 3.12): - .script-ext-wrap y .resource-badge: centrados, tamaño reducido a 72px en móvil - .script-ext: tamaño de fuente reducido coherentemente - Gaps y padding normalizados para los tres tipos de ficha

Archivos modificados: theme.scss, docs/ (recompilado con quarto render)

2026-06-30 — Fase 0 (complemento): fix overflow panel intro en móvil

Problema: el texto monoespaciado del panel .glass-intro (descripción de cada sección) desbordaba el contenedor en móvil, creando scroll horizontal.

Solución aplicada en theme.scss: - overflow-x: hidden en body — contiene cualquier desborde global - max-width: 100%; overflow-wrap: break-word en .glass-intro a ≤768px - letter-spacing: 0.01em en .intro-text a ≤768px — reduce el tracking del mono

Archivos modificados: theme.scss, docs/

2026-06-30 — Fase 2: Filtro UI por tags

Qué se hizo: se agregó un sistema de chips de filtrado por tag en las tres páginas de contenido (lecturas.qmd, scripts.qmd, recursos.qmd).

Implementación: - CSS en theme.scss (sección 3.12): .tag-chips-wrap, .tag-chip, .tag-chip--active - HTML: <div class="tag-chips-wrap" id="[page]-tags"></div> dentro de .glass-intro - JS en cada QMD: IIFE que puebla los chips desde el array de datos + funciones filterBooks/filterScripts/filterRecursos + renderBooks/renderScripts/renderRecursos - Variables de estado con nombre único por página (activeBookTag, activeScriptTag, activeRecursoTag) para evitar colisiones

Comportamiento: chip “ver todo” activo por defecto; al hacer clic en un tag se re-renderiza la columna de fichas mostrando solo las entradas con ese tag. Los modales de lecturas siguen pre-renderizados completos (independiente del filtro activo).

Archivos modificados: theme.scss, lecturas.qmd, scripts.qmd, recursos.qmd, README.md (schema + roadmap), LOG.md

2026-06-30 — Fase 3: Paginación (6 items/página)

Qué se hizo: paginación client-side en las tres páginas de contenido. Muestra 6 entradas por página; si hay ≤6 resultados (situación actual), el control queda vacío y .pagination-wrap:empty lo oculta automáticamente vía CSS. Lista el número de páginas cuando sea necesario.

Implementación: - CSS en theme.scss (sección 3.13, Responsive renombrado a 3.14): .pagination-wrap, .page-btn, .page-btn--active - HTML: <div class="pagination-wrap" id="[page]-pagination"></div> insertado entre .lecturas-layout y el resto del HTML en cada página - JS por página: - ITEMS_PER_PAGE = 6 (constante local por archivo) - currentXPage = 1 (estado de página actual) - renderX() actualizado: filtra → pagina con .slice() → llama renderXPagination() - renderXPagination(totalPages): genera botones numerados; si totalPages ≤ 1, vacía el div - goToXPage(p): actualiza página, re-renderiza y hace scroll suave al inicio de las fichas - filterX() actualizado: resetea currentXPage = 1 antes de re-renderizar

Comportamiento cuando hay más de 6 items: aparecen botones numerados (1, 2, 3…) bajo las fichas; el filtro por tag resetea siempre a página 1.

2026-06-30 — Fase 4: Página /explorar + tag-cloud en Home

Qué se hizo: 1. Nueva página explorar.qmd — vista unificada de todos los contenidos (libros, scripts, recursos) en un solo lugar. Carga los 3 JSONs vía R, combina en ALL_DATA con campo _type, muestra chips con conteo (metodología (4)) y filtra client-side. Soporta URL hash para pre-selección desde el Home (explorar.html#metodología). Paginación de 6 items/página integrada con el filtro. 2. Tag-cloud en index.qmd — sección “Explorar por tema” bajo el hero, con R que agrega tags de los 3 JSONs e inyecta TAG_COUNTS. JS genera los chips como <a href> apuntando a explorar.html#[tag]. Chips invertidos (crema sobre azul) vía .home-tagcloud-section. 3. Navbar — nueva entrada “Explorar” en _quarto.yml apuntando a explorar.qmd.

Detalles técnicos: - explorarCardHtml(item): card unificada que adapta el visual según item._type (cover+stars para libros, .script-ext para scripts, .resource-badge para recursos) - history.replaceState() actualiza el hash en la URL al filtrar en explorar - .home-tagcloud-section .tag-chip invierte colores (fondo azul del Home) - a.tag-chip: text-decoration: none; display: inline-flex para chips como links - .chip-count: cuenta de entradas por tag, estilo sutil (opacity: 0.6; font-size: 0.9em)

Archivos modificados/creados: explorar.qmd (nuevo), index.qmd, _quarto.yml, theme.scss, README.md (roadmap), LOG.md

2026-07-01 — Ensayos: nueva página funcional

Qué se hizo: se convirtió la página ensayos.qmd de placeholder (“En construcción…”) a página funcional completa, con el mismo sistema de fichas, filtro por tags y paginación que el resto del sitio.

Schema de data/ensayos.json:

Campo Tipo Descripción
id string Identificador único
tags string[] Tags temáticos
fecha string Fecha de añadido (display)
tipo string Tipo de trabajo: ENSAYO, TESIS, PON, ART, CAP, etc. (texto del badge)
title string Título del trabajo
author string Autor(es)
year string Año
caption string Descripción breve
citation string Cita formateada (HTML permitido para <em>)
url string Enlace al trabajo (vacío si no disponible aún)

Comportamiento del badge: el campo tipo aparece como badge en la ficha (igual que extension en scripts). Valores sugeridos: ENSAYO, TESIS, PON (ponencia), ART (artículo), CAP (capítulo).

Integración en Explorar: explorar.qmd e index.qmd ahora cargan también ensayos.json; los ensayos aparecen en el explorador unificado y sus tags se suman al tag-cloud del Home.

Archivos creados/modificados: data/ensayos.json (nuevo), ensayos.qmd (reescrito), explorar.qmd (ENSAYOS_DATA + rama de card), index.qmd (R chunk), README.md, LOG.md
