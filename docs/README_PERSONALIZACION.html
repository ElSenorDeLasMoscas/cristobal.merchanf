Panel de control del diseño — theme.scss

Este sitio Quarto tiene su estética rediseñada por tokens. Toda decisión visual (color, tipografía, espaciado, hairlines, duotono) se controla desde un único archivo: theme.scss. El contenido, la navegación y la funcionalidad no se tocaron: viven en los .qmd y en _quarto.yml.

Idea de primeros principios: defines unos pocos tokens atómicos (los únicos valores “de marca”) y todo lo demás se deriva de ellos. Cambias un token → el cambio se propaga de forma coherente por todo el sitio. Las reglas de estilo nunca repiten un color o una fuente “a mano”: siempre consumen un token.

1. Dónde está cada cosa

Archivo Qué contiene ¿Tocar?
theme.scss El tema completo: tokens (bloque scss:defaults) + reglas (scss:rules). Sí, aquí personalizas.
_quarto.yml Enlaza el tema (theme: [theme.scss]) y carga las fuentes (Google Fonts). Solo para cambiar de fuente o de archivo de tema.
custom.scss Tema antiguo (glassmorphism morado). Queda como respaldo. No se carga. No; es tu copia de seguridad.
index.qmd, lecturas.qmd, scripts.qmd, recursos.qmd, ensayos.qmd Contenido (HTML/JS, listados, modal). No (no hace falta para reestilizar).
data/*.json Datos (libros, scripts, recursos). Solo para cambiar contenido, no estilo.

La estructura de tokens dentro de theme.scss:

/*-- scss:defaults --*/
   1. TOKENS ATÓMICOS        ← edita aquí el 95% de las veces
   2. MAPEADO A BOOTSTRAP    ← traduce tokens → variables del framework
/*-- scss:rules --*/
   3. REGLAS                 ← consumen tokens; rara vez hay que tocarlas

2. Tabla de tokens

Todos están en theme.scss, sección 1. TOKENS ATÓMICOS. Cada uno termina en !default (puedes sobre-escribirlo sin borrar la línea original si prefieres).

El bloque 2. MAPEADO A BOOTSTRAP traduce estos tokens a las variables del framework ($primary, $body-bg, $body-color, $link-color, $headings-font-family, $font-family-monospace, $navbar-bg…). Normalmente no necesitas tocarlo: cambia el token y el mapeo se actualiza solo.

3. Recetas frecuentes

3.1 Cambiar el azul (el color de marca)

  1. Abre theme.scss → sección 1.1 Color.
  2. Cambia solo $token-blue: #1d24e6; por tu hex.
  3. quarto render. Fondo, bordes, paneles invertidos y botones se actualizan juntos.

Para cambiar el crema, edita $token-paper. Para invertir TODO el sitio (crema de fondo, azul de texto) intercambia los valores de $token-bg y $token-fg.

3.2 Cambiar la tipografía

  1. Carga la fuente en _quarto.yml → dentro de include-in-header: está el <link href="https://fonts.googleapis.com/css2?family=Bodoni+Moda…&family=Space+Mono…">. Sustituye la familia por la que quieras (cualquier Google Font).
  2. Apunta el token en theme.scss → 1.2 Tipografía:
    • serif display → $token-font-display
    • monoespaciada → $token-font-mono Deja siempre fallbacks libres al final (…, Georgia, serif / …, monospace).
  3. quarto render.

Alternativas Didone libres: Bodoni Moda, Playfair Display, Cormorant. Mono libres: Space Mono, JetBrains Mono, IBM Plex Mono.

3.3 Invertir una sección (figura ↔︎ fondo)

  • Las tarjetas alternan solas: las pares se invierten vía .book-card:nth-child(even) (sección 3.8 de theme.scss). Para invertir el patrón, cambia even por odd.
  • Para forzar un panel concreto a un estilo, los mixins ya existen en theme.scss (sección 3.0): @include panel-paper; (crema con texto azul) o @include panel-ink; (azul con texto crema + hairline). Aplícalos a la clase que quieras.

3.4 Ajustar el duotono de las imágenes

  • En theme.scss → 1.5 Imágenes, edita $token-duotone:
    • Más intenso / más azul: sube saturate(5) (p. ej. saturate(8)).
    • Tono del azul: ajusta hue-rotate(200deg).
    • Más contraste tipo grabado: sube contrast(1.1).
    • Desactivar: pon $token-duotone: none;.
  • Se aplica a portadas (.book-img, .modal-cover). No reemplaza ninguna imagen: solo las trata por CSS.

3.5 Quitar los números de bloque decorativos (#01, #02…)

  • En theme.scss → 1.6, pon $token-counter-prefix: "";.

3.5b Color al seleccionar texto

  • Sobre el fondo primario (morado), el resaltado es crema: regla ::selection en theme.scss → sección 3.1.
  • Sobre fondos claros (cajas de código, paneles crema), el resaltado es el primario translúcido ($token-selection-light). Para hacerlo más/menos visible cambia el 0.28 del token; para abarcar más superficies, añade su selector a la lista de reglas …::selection de la sección 3.1.

3.6 El home en dos columnas

  • La portada (index.qmd) agrupa su contenido en dos bloques: .hero-col-left (wordmark + rol + bio + redes) y .hero-col-right (etiqueta “Explorar” + tarjetas de navegación), dentro de .hero-split.
  • El reparto y el espacio entre columnas se controlan en theme.scss → sección 3.3 Hero, en la regla .hero-split:
    • Proporción de columnas: grid-template-columns: 1.05fr 0.95fr;
    • Separación: gap: $token-space * 2.6;
  • En pantallas ≤ 991px se apila en una sola columna y se vuelve a centrar (media query justo debajo). Cambia ese 991px para ajustar cuándo colapsa.

3.7 Tamaño / marco de las portadas e íconos

  • En theme.scss → sección 3.8, la regla .book-img define el tamaño (width/height), el paspartú crema (border: 6px solid $token-paper) y la sombra dura (box-shadow). Las mismas ideas se repiten en .modal-cover, .script-ext y .resource-badge.
  • Para portadas más grandes/pequeñas cambia el width/height de .book-img.
  • Para más/menos “aire” entre la imagen y el texto, ajusta el gap y el padding de .book-card (misma sección).
  • Animación al pasar el puntero: la tarjeta muestra una fina línea de acento que crece por el costado izquierdo (regla .book-card::before / .book-card:hover::before, sección 3.8). Para hacerla más gruesa cambia el width: 5px del :hover; para más lenta/rápida, el transition (0.28s).

5. Supuestos y limitaciones declarados

  • Proyecto: Quarto website con format: html, output en docs/. Confirmado.
  • Tema previo: sí existía (quartz + custom.scss). Se creó theme.scss nuevo y se enlazó; custom.scss se conserva como respaldo (no se carga).
  • Valores de la referencia: el azul (#1d24e6) y las fuentes (Bodoni Moda / Space Mono) son aproximaciones de la referencia, expuestas como tokens para que las ajustes.
  • Fuentes: servidas como equivalentes libres vía Google Fonts, con fallbacks del sistema.
  • Cuerpo en mono: la referencia usa mayúsculas en mono para nav/etiquetas. Se aplicó mayúsculas a navegación, etiquetas, botones y títulos, pero no a los párrafos largos (reseñas) para no perjudicar la legibilidad. Es una decisión de diseño reversible (quita text-transform: uppercase donde no lo quieras).
  • Imágenes de referencia: sí estaban adjuntas en la sesión; el diseño las emula. El duotono se aplica por CSS a las imágenes de contenido existentes.
