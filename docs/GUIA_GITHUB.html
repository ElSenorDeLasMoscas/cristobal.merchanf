Guía: Subir y actualizar el sitio en GitHub (vía VS Code)

Guía paso a paso para publicar el sitio Quarto cristobal.merchan en GitHub y mantenerlo actualizado, usando la interfaz gráfica de VS Code.

  • Repositorio: https://github.com/ElSenorDeLasMoscas/cristobal.merchanf
  • Carpeta del proyecto: repo\www\cristobal.merchan
  • Sitio publicado: https://elsenordelasmoscas.github.io/cristobal.merchanf/

🧭 Cómo funciona (lee esto primero)

El sitio se escribe en archivos fuente (.qmd, theme.scss, data/…) y Quarto los compila a HTML dentro de la carpeta docs/.

GitHub Pages no sabe compilar Quarto por sí solo (y tu sitio usa R, que complica la compilación automática). Por eso usamos el método más simple y confiable:

  1. Tú compilas en tu computador con quarto render (o Ctrl+Shift+K en VS Code).
  2. Subes a GitHub tanto las fuentes como la carpeta docs/ ya compilada.
  3. GitHub Pages publica directamente lo que hay en docs/.

⚠️ Regla de oro: cada vez que cambies algo del sitio, primero compila (quarto render) y después subes. Si subes sin compilar, el sitio publicado no reflejará tus cambios.

📌 Por este método, la carpeta docs/ SÍ debe subirse a GitHub. En el archivo .gitignore la línea /docs/ debe estar comentada (con # delante) o no existir. Ya quedó así: #/docs/.

PARTE 1 — Primera carga (solo se hace una vez)

Paso 1. Abrir el proyecto en VS Code

  1. Abre VS Code.
  2. File → Open Folder…
  3. Selecciona la carpeta: C:\Users\bernardo.rojas\OneDrive\Desktop\magister\repo\www\cristobal.merchan
  4. Si aparece un aviso de confianza, haz clic en “Yes, I trust the authors”.

Paso 2. Compilar el sitio (importante)

Antes de subir, asegúrate de tener el sitio compilado y actualizado:

  1. Abre la terminal integrada: menú Terminal → New Terminal (o Ctrl+Ñ).

  2. Escribe y ejecuta:

    quarto render

  3. Espera a que termine. Debe compilar las 5 páginas sin errores y dejar todo en la carpeta docs/.

Paso 3. Abrir el panel de control de versiones (Source Control)

  1. En la barra lateral izquierda, haz clic en el icono de Source Control (parece tres círculos conectados por líneas) o presiona Ctrl+Shift+G.
  2. Si VS Code dice que no es un repositorio git, haz clic en “Initialize Repository”. (Si ya muestra archivos, salta este paso.)

Paso 4. Preparar todos los archivos (Stage)

  1. En el panel de Source Control verás una lista de archivos bajo “Changes”.

  2. Pasa el mouse sobre el encabezado “Changes” y haz clic en el icono + (“Stage All Changes”). Esto mueve todos los archivos a “Staged Changes”.

    La carpeta docs/ debe aparecer en la lista. Es correcto: con este método sí se sube.

Paso 5. Escribir el mensaje y hacer Commit

  1. En la caja de texto de arriba (dice “Message”), escribe:

    Primera versión del sitio

  2. Haz clic en el botón “Commit” (o presiona Ctrl+Enter).

  3. Si VS Code te pide configurar tu identidad, ejecuta esto una vez en la terminal y repite el commit:

    git config --global user.name "Cristóbal Merchan"
git config --global user.email "cristobal.merchan98@gmail.com"

Paso 6. Conectar con el repositorio de GitHub

En la terminal integrada de VS Code, ejecuta:

git remote add origin https://github.com/ElSenorDeLasMoscas/cristobal.merchanf.git
git branch -M main

Si responde error: remote origin already exists, primero ejecuta git remote remove origin y vuelve a poner la línea git remote add ….

Paso 7. Subir por primera vez (Push)

En la terminal:

git push -u origin main
  • La primera vez se abrirá una ventana del navegador para iniciar sesión en GitHub. Acepta/autoriza.
  • Cuando termine, verás algo como branch 'main' set up to track 'origin/main'.

Paso 8. Verificar que subió

Abre en el navegador: https://github.com/ElSenorDeLasMoscas/cristobal.merchanf

Deberías ver tus archivos: README.md, theme.scss, los .qmd, data/ y la carpeta docs/.

PARTE 2 — Activar GitHub Pages (solo se hace una vez)

  1. Abre: https://github.com/ElSenorDeLasMoscas/cristobal.merchanf/settings/pages
  2. En “Build and deployment” → “Source”, elige: Deploy from a branch.
  3. En “Branch”:
    • Rama: main
    • Carpeta: /docs ← (¡importante! NO /(root))
  4. Haz clic en Save.
  5. Espera 1–2 minutos. Refresca la página: arriba aparecerá el enlace del sitio: https://elsenordelasmoscas.github.io/cristobal.merchanf/
  6. Ábrelo. Debe mostrar la página de inicio (no el README).

Si ves el README en lugar del sitio, casi siempre es porque la carpeta quedó en /(root) en lugar de /docs. Vuelve al paso 3 y corrígelo.

PARTE 3 — Actualizar el sitio (cada vez que hagas cambios)

Este es el flujo que repetirás siempre. Son 4 pasos: editar → compilar → commit → push.

Paso 1. Edita lo que necesites

  • Estética → theme.scss
  • Contenido de libros / scripts / recursos → archivos en data/
  • Páginas → los .qmd

Paso 2. Compila (¡no lo olvides!)

En la terminal de VS Code:

quarto render

Si no compilas, el sitio publicado no mostrará tus cambios.

Paso 3. Commit en VS Code

  1. Ve al panel Source Control (Ctrl+Shift+G).
  2. Pasa el mouse sobre “Changes” y haz clic en + (Stage All Changes).
  3. Escribe un mensaje corto que describa el cambio, por ejemplo:
    • Agrego reseña de Kuhn
    • Ajusto color del tema
    • Nuevo script de bibliometría
  4. Haz clic en Commit.

Paso 4. Push (subir)

Tienes dos formas equivalentes:

  • Opción A (botón): haz clic en “Sync Changes” (la flecha circular) en el panel de Source Control o en la barra de estado azul de abajo.

  • Opción B (terminal):

    git push

Espera 1–2 minutos y recarga https://elsenordelasmoscas.github.io/cristobal.merchanf/ para ver los cambios publicados.

💡 Truco: si el navegador muestra una versión vieja, fuerza la recarga con Ctrl+F5 o abre el sitio en una ventana de incógnito.

✅ Resumen rápido (para tener a mano)

Para actualizar el sitio, siempre:

# 1. (editas tus archivos)
# 2. Compilas:
quarto render
# 3. En Source Control: Stage All (+), escribe mensaje, Commit
# 4. Subes:
git push

🆘 Problemas frecuentes

Síntoma Causa probable Solución
El sitio publicado muestra el README, no la página Pages está en /(root) Settings → Pages → Branch main, carpeta /docs, Save
Subí cambios pero el sitio no los muestra Olvidaste quarto render antes del commit Ejecuta quarto render, vuelve a commit + push
remote origin already exists El remote ya estaba configurado git remote remove origin y vuelve a agregarlo
Pide usuario/correo al hacer commit Git sin identidad configurada Ejecuta los dos git config --global … del Paso 5
El push pide login y no avanza Falta autenticación de GitHub Sigue la ventana del navegador que abre VS Code; autoriza
Cambios en docs/ no aparecen para subir docs/ está siendo ignorado Revisa .gitignore: la línea de docs/ debe estar comentada (#/docs/)

📎 Notas

  • Nunca edites a mano los archivos dentro de docs/: son generados por Quarto y se sobrescriben en cada quarto render.
  • El archivo .gitignore debe mantener docs/ sin ignorar (comentado con #) para que este método funcione.
  • La guía de personalización del diseño (colores, fuentes, etc.) está en cristobal.merchan/README_PERSONALIZACION.md.
